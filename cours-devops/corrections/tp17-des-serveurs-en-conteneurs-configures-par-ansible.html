Correction type — Travail pratique 17

Des « serveurs » en conteneurs, configurés par Ansible

Une solution complète, étape par étape : ce qu'il faut produire, la commande ou le fichier clé, le résultat qui prouve que ça marche, et les pièges. Ta solution peut différer ; ce qui compte, c'est que chaque preuve soit là.

Étapes de la correction
  1. Trois hôtes cibles en conteneurs, et l'inventaire
  2. Rôles : commun, nginx, docker ; playbook site.yml
  3. Variables, précédence, Vault
  4. Déploiement avec serial, block/rescue, delegate
  5. Performance, lint, Molecule
  6. Ce que le relecteur doit trouver
  7. Questions de relecteur
Énoncé
  1. Inventaire web1, web2, db1 avec groupes, group_vars. ansible all -m ping vert.
  2. Rôle common : paquets de base, fuseau horaire, utilisateur d'exploitation, durcissement SSH (pas de root, pas de mot de passe, MaxAuthTries) via template avec validate: sshd -t -f %s et handler.
  3. Rôle docker : installe Docker depuis le dépôt officiel (clé GPG, dépôt apt, paquet), ajoute deploy au groupe docker.
  4. Rôle crisisshield_api : dépose un compose.yaml templaté (tag d'image en variable), un fichier de secrets depuis Ansible Vault, et lance community.docker.docker_compose_v2. Remarque : le Docker dans le conteneur cible ne pourra pas démarrer sans privilèges ; contente-toi de vérifier l'installation et le dépôt du compose, ou lance les cibles en privileged pour aller au bout (note le risque).
  5. Idempotence : second passage entièrement ok. Prouve-le avec la sortie du récapitulatif.
  6. Molecule sur le rôle common (driver docker), avec un test qui vérifie que PermitRootLogin no est présent. ansible-lint propre. Les deux dans la CI.
  7. Opération ad hoc : un playbook rotate-secret.yml qui change le mot de passe de la base dans le vault, le redéploie sur db1 puis sur les web, dans cet ordre, avec serial: 1.
  8. Flux et stratégies : réécris le déploiement de l'API avec serial, block/rescue/always, retrait et remise dans un « load balancer » simulé (le proxy nginx du TP 3, piloté par un endpoint ou un fichier), until sur la readiness, et un rollback. Provoque un échec sur un hôte et vérifie l'arrêt global et le retour arrière. Compare la durée en strategy: linear et free avec forks à 5 puis à 50 et le pipelining.
  9. Variables : reproduis l'exercice 17.4 en créant volontairement le conflit, tranche avec ansible-inventory --host, puis range les variables selon la règle (defaults du rôle, inventaire, extra-vars ponctuels). Deux identités de vault (dev, prod) et une valeur chiffrée inline.
  10. Erreurs : reproduis cinq lignes du tableau 17.8 (UNREACHABLE, Python absent, become, changed permanent, secret dans les logs) et corrige chacune ; ansible-lint profil production vert.
Étape 1

Trois hôtes cibles en conteneurs, et l'inventaire

for h in web1 web2 db1; do docker run -d --name $h --network tp17 -p 0:22 rastasheep/ubuntu-sshd:18.04 >/dev/null; done   # image de labo avec sshd (root:root) ; ou une image Ubuntu + openssh-server + ta clé
cat > inventory/lab.ini <<'EOF'
[web]
web1 ansible_host=web1
web2 ansible_host=web2
[db]
db1 ansible_host=db1
[all:vars]
ansible_user=root
ansible_ssh_private_key_file=/w/keys/lab
ansible_python_interpreter=/usr/bin/python3
EOF
alias ans='docker run --rm -it -v "$PWD:/w" -w /w --network tp17 -e ANSIBLE_HOST_KEY_CHECKING=False willhallonline/ansible:2.17-alpine'
ans ansible all -i inventory/lab.ini -m ping
web1 | SUCCESS => { "ping": "pong" } web2 | SUCCESS … db1 | SUCCESS
  • Les hôtes n'ont ni agent ni Ansible : SSH et Python suffisent. Si Python manque : ansible.builtin.raw: apt-get install -y python3 en premier.
  • host_key_checking désactivé en labo seulement ; en production, ssh-keyscan alimente known_hosts.
Étape 2

Rôles : commun, nginx, docker ; playbook site.yml

ans ansible-galaxy init roles/common && ans ansible-galaxy init roles/nginx
cat > roles/nginx/tasks/main.yml <<'EOF'
- name: Paquet nginx
  ansible.builtin.apt: { name: nginx, state: present, update_cache: true }
- name: Configuration du site
  ansible.builtin.template: { src: site.conf.j2, dest: /etc/nginx/sites-available/default, validate: 'nginx -t -c /etc/nginx/nginx.conf', backup: true }
  notify: reload nginx
- name: Service actif
  ansible.builtin.service: { name: nginx, state: started, enabled: true }
EOF
cat > roles/nginx/handlers/main.yml <<'EOF'
- name: reload nginx
  ansible.builtin.service: { name: nginx, state: reloaded }
EOF
cat > roles/nginx/defaults/main.yml <<'EOF'
nginx_upstream: "api:8080"
EOF
cat > site.yml <<'EOF'
- hosts: all
  become: true
  roles: [common]
- hosts: web
  become: true
  roles: [nginx]
EOF
ans ansible-playbook -i inventory/lab.ini site.yml && ans ansible-playbook -i inventory/lab.ini site.yml | grep 'changed='
PLAY RECAP : web1 ok=6 changed=3 … (1er passage) web1 ok=6 changed=0 … (2e passage : idempotent)
  • changed=0 au second passage est la preuve d'idempotence demandée par le chapitre.
  • validate: sur le template : une configuration invalide n'est jamais écrite ; backup: true garde l'ancienne.
Étape 3

Variables, précédence, Vault

cat > group_vars/web.yml <<'EOF'
nginx_upstream: "api:9090"
EOF
ans ansible-inventory -i inventory/lab.ini --host web1 --yaml
ans ansible-vault encrypt_string --vault-id dev@prompt 'S3cr3t' --name db_password >> group_vars/db.yml
ans ansible-playbook -i inventory/lab.ini site.yml --vault-id dev@prompt -e nginx_upstream=api:7070 --check --diff | grep -A3 upstream
nginx_upstream: api:9090 (group_vars gagne sur defaults) … -e gagne sur tout : le diff montre api:7070
  • ansible-inventory --host tranche toute question de précédence.
  • Une valeur chiffrée inline reste diffable dans Git ; un fichier entier chiffré ne l'est pas.
Étape 4

Déploiement avec serial, block/rescue, delegate

cat > deploy.yml <<'EOF'
- hosts: web
  serial: "50%"
  max_fail_percentage: 0
  any_errors_fatal: true
  become: true
  tasks:
    - name: Retirer du load balancer
      ansible.builtin.file: { path: "/w/lb/{{ inventory_hostname }}.up", state: absent }
      delegate_to: localhost
    - block:
        - name: Déployer la version
          ansible.builtin.copy: { content: "{{ app_version }}", dest: /var/www/html/version.txt }
        - name: Readiness
          ansible.builtin.uri: { url: "http://localhost/version.txt", return_content: true }
          register: r
          until: app_version in r.content
          retries: 10
          delay: 1
      rescue:
        - ansible.builtin.copy: { content: "rollback", dest: /var/www/html/version.txt }
        - ansible.builtin.fail: { msg: "déploiement annulé sur {{ inventory_hostname }}" }
      always:
        - name: Remettre dans le load balancer
          ansible.builtin.file: { path: "/w/lb/{{ inventory_hostname }}.up", state: touch }
          delegate_to: localhost
EOF
ans ansible-playbook -i inventory/lab.ini deploy.yml -e app_version=1.2.0
ans ansible-playbook -i inventory/lab.ini deploy.yml -e app_version=1.3.0 -e '{"ansible_become": false}' ; echo "code $?"   # échec provoqué sur un hôte
web1 puis web2, un à la fois, readiness OK web1 : FAILED → rescue : rollback, always : remis dans le LB ; le play s'arrête (any_errors_fatal)
  • serial limite le rayon d'impact ; rescue ramène l'hôte dans un état sain ; always garantit qu'il revient dans le load balancer même en échec.
  • Le « load balancer » est simulé par des fichiers sur le contrôleur : le mécanisme est le même avec une API.
Étape 5

Performance, lint, Molecule

printf '[defaults]\nforks = 50\ngathering = smart\nfact_caching = jsonfile\nfact_caching_connection = /tmp/facts\nstdout_callback = yaml\n[ssh_connection]\npipelining = True\n' > ansible.cfg
time ans ansible-playbook -i inventory/lab.ini site.yml >/dev/null
docker run --rm -v "$PWD:/w" -w /w pipelinecomponents/ansible-lint ansible-lint --profile production
# Molecule : molecule init scenario -r nginx -d docker ; molecule test (dans un conteneur avec le socket)
real 0m9s (contre 0m21s sans pipelining ni cache de facts) Passed: 0 failure(s), 0 warning(s) on 14 files.
  • Les cinq réglages d'ansible.cfg divisent le temps par deux sur trois hôtes ; sur cent, par dix.
  • ansible-lint profil production : noms complets des modules, tâches nommées, pas de shell quand un module existe.
